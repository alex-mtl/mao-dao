# Заметки из первого обсуждения (2026-10-14)

## Задача
- Подписчики из TikTok по ссылке подписываются на Telegram-бота и при знакомстве сообщают свой TikTok-аккаунт.
- Когда LIVE-игра пользователя регистрирует подарок от этого зрителя, бот присылает ему в Telegram инструкции или задаёт вопросы.

## Валидация TikTok-аккаунта (предложено, не утверждено)
- Рекомендуемый вариант: «код в чате эфира». Бот выдаёт код (`DV-4821`), зритель пишет его комментарием в LIVE,
  источник событий эфира видит автора комментария (uniqueId + постоянный числовой userId) и сообщает боту → привязка.
  Хранить числовой userId, не ник.
- Отвергнуто/хуже: код в био профиля (парсинг TikTok — хрупко, против ToS); TikTok Login Kit (нужно одобрение,
  другой идентификатор — open_id, не совпадает с LIVE-событиями).

## Открытый главный вопрос
На чём сделана игра и откуда она получает события подарков? Эффект Effect House, вероятно, не может делать
внешние HTTP-запросы → может понадобиться отдельный приёмник событий эфира (программа на ПК стримера).

## Предварительная zero-cost архитектура (обсуждается)
- Telegram webhook → AWS Lambda (Function URL), DynamoDB on-demand для подписчиков/привязок,
  токен бота в SSM Parameter Store (бесплатно, не Secrets Manager). Endpoint для событий игры с аутентификацией.
- Ограничения пользователя: AWS-бюджет $1 с hard-stop на 50% (см. C:\projects\claude\aws-for-claude),
  CLI-инструменты только через Docker, стек выбирается с нуля под задачу, новые ресурсы — тег Project=<id> + реестр.

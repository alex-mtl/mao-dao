# quiz-factory — вопросы для викторин из Wikidata

Вопросы с 4 вариантами ответа и запасом неправильных ответов, на русском. Факты берутся из Wikidata (CC0),
формулировки задают шаблоны в стиле викторины, неправильные ответы — правильные ответы на соседние вопросы того же типа.
**Модель не нужна**: всё работает на компьютере за несколько минут (запросы к Wikidata кешируются в `data/cache`).

На 2026-11-08 на mao-dao: **5755 вопросов в 290 квизах** (8 категорий), `data/report-all.html` — все вопросы.

```
build-geo.mjs       география: столицы, города, горы, высоты, высшие точки, реки, валюты, языки
build-sport.mjs     спорт: Олимпиады, ЧМ и Евро по футболу, звёзды спорта, клубы
build-culture.mjs   литература (авторы книг), искусство (художники, музеи), кино (режиссёры, год выхода), музыка (оперы, группы)
build-science.mjs   наука: химические элементы, Нобелевские премии
build-history.mjs   история: сражения, начало войн
plan.mjs            всё вместе -> квизы по 20: категория + уровень, типы вперемешку -> data/plan.json
import.mjs          data/plan.json -> mao-dao (POST /internal/quizzes/import)
report-plan.mjs     data/plan.json -> data/report-all.html
lib/                Wikidata с кешем, общие правила, родительный падеж стран (genitive.mjs)
```

```bash
node plan.mjs --target=5600          # новых вопросов; распределение по категориям — SHARE в plan.mjs
node import.mjs --dry-run
node import.mjs                      # секрет: ~/.mao-dao/quiz-import-secret
node report-plan.mjs
```

Повторный запуск безопасен: `data/assignments.json` помнит, какой вопрос в каком квизе, новые вопросы идут в новые
квизы, а API находит вопрос по ключу (`capital:Q33`) и обновляет только текст и запас, не трогая ответы и историю.
`data/existing.json` — выгрузка вопросов, уже бывших на сайте до перехода на план (их 3 неправильных ответа сохранены).

## Порции (с 2026-11-09)

```
build-people.mjs    люди 7 групп: «В каком году родился / умерла …?», «… — из какой страны?»
build-more.mjs      43 типа: острова, озёра, ЮНЕСКО, здания, архитекторы, годы картин и книг, герои книг, страны фильмов
                    и сериалов, альбомы, песни, игры, компании, автомобили, спутники, созвездия, семейства и отряды,
                    блюда, договоры, революции, катастрофы, клубы, стадионы, университеты, письменность
batch.mjs           всё вместе -> порции data/batches/NNN.json и импорт на mao-dao
```

```bash
node batch.mjs --size=5000 --batches=10      # 10 порций по ~5000 новых вопросов
node batch.mjs --plan-only                   # только составить порции, без импорта
```

После падения или зависания сети — просто запустить ту же команду ещё раз: `NNN.done` помнит импортированные квизы
(сначала доимпортируется начатая порция, потом составляются следующие), `assignments.json` — какие вопросы уже заняты.
Вопрос не берётся второй раз; уровень — по известности среди всех кандидатов типа, так что от порции к порции он не
меняется, а в каждой порции есть все три уровня. Категории — все теги сайта, кроме «Математики»
(новые: Видеоигры, Техника и компании, Природа, Еда и напитки, Эрудиция, Языки).

## Квизы

- 20 вопросов, одна категория, один уровень; типы вопросов внутри категории чередуются (столицы, горы, реки…).
- Уровень — по известности внутри типа среди отобранных (число языковых Википедий): 30% лёгкий, 40% средний, 30% сложный.
- Один и тот же правильный ответ — не больше 6 раз на тип, если ответ — человек или музей (не 30 книг Агаты Кристи).
- Вопрос, текст которого совпадает с другим («Сердце», «Динамо», «Турецко-персидская война»), выбрасывается.

## Неправильные ответы: 14 на вопрос

Хранятся на mao-dao в `questions.wrong_pool`; первые 3 — те же, что в ответах квиза, ещё 11 — запас, чтобы игровой
движок (TikTok) мог менять варианты при повторе вопроса. Порядок: самые правдоподобные первыми — близость
(тот же континент, та же страна и эпоха, соседние элементы таблицы) и известность, среди равных — небольшое перемешивание.

## Правила качества

- У темы и у ответа есть статья в русской Википедии и русская метка; ответ до 32 символов, без латиницы.
- У свойства ровно **одно** значение лучшего ранга: две столицы, спорные границы, соавторы, несколько дат — мимо.
- Страны — действующие суверенные государства. Не берутся: «год основания города» (часто первое упоминание),
  незавершённые войны, «кто открыл или изобрёл» (слишком разнородные данные), балеты (нет данных).
- Неправильный ответ гарантированно неверен:
  - столицы — крупные города страны, кроме тех, что были столицей или резиденцией (Абиджан, Тель-Авив, Алматы);
  - горы — без соседних стран (вершина на границе);
  - реки — без водоёмов, частью которых является устье, и без океанов, если ответ не океан;
  - Олимпиады — другие города-хозяева и крупные города стран, никогда не принимавших Игры (не Таллин для 1980);
  - языки — без языков, на которых говорят в той же стране;
  - люди — той же профессии (писатели, режиссёры, художники, композиторы), но не известные в первую очередь другим
    (Обама среди писателей, Рассел Кроу среди режиссёров); музеи — только музеи.
- Спортсмены — по профессии, без людей, известных другим (Нильс Бор стоял в воротах, Буш играл в регби).

## Формулировки

«Столица Финляндии?», «Самая высокая вершина Австралии?», «Высота Монблана?», «В какой стране находится Рио-де-Жанейро?»,
«Куда впадает Сена?», «Валюта Японии?», «Где прошла летняя Олимпиада-1980?», «Месси — какой вид спорта?»,
«Кто написал «Война и мир»?», «Кто снял фильм «Титаник»?», «Битва при Ватерлоо — в каком году?».
Родительный падеж стран — `lib/genitive.mjs` (правила + исключения); неизвестное название — формулировка без склонения.

## Kaggle (не используется)

`kaggle.mjs`, `kaggle/polish.py`, `finalize.mjs`, `compare.mjs`, `report.mjs` — прежний этап проверки моделью на Kaggle
(GigaChat3.1-10B, GGUF через llama-server из образа `ghcr.io/ggml-org/llama.cpp:server-cuda`). Отключён: проверка
находила почти только собственные ошибки модели. Пригодится для задач, которые скриптом не сделать (пояснения к
ответам, вопросы не из Wikidata, переводы).

# quiz-factory — генератор вопросов для викторины

Вопросы с 4 вариантами ответа из открытых данных (Wikidata, CC0). Формулировки задают шаблоны в стиле викторины
(«Столица Финляндии?», «Самая высокая вершина Австралии?», «Высота Монблана?», «В какой стране находится Рио-де-Жанейро?»,
«Куда впадает Сена?»). Модель на бесплатном GPU Kaggle только склоняет названия и вслепую отвечает на готовый вопрос,
**фактов не придумывает и ничего не выбрасывает**: несогласие с Wikidata — лишь пометка в отчёте. Пока русский язык и география.

Модель: **GigaChat3.1-10B-A1.8B** (Сбер, MIT), версия GGUF q8_0 через llama.cpp: `--model=ai-sage/GigaChat3.1-10B-A1.8B-GGUF:q8_0`.
Бинарник llama-server берётся из двух верхних слоёв официального образа `ghcr.io/ggml-org/llama.cpp:server-cuda-b12199`
(CUDA 12.8, Ubuntu 24.04, как на Kaggle; ~190 МБ, 5 с), без Docker и без компиляции; если не вышло, собирается из исходников (~30 мин).
Сравнение на одних вопросах: против Qwen2.5-7B — 178 верных против 167, все склонения без ошибок;
GGUF дал те же ответы, что bf16 через transformers (100 из 100), а проверка шла в 4–24 раза быстрее
(0,09–0,45 с на вопрос против 2,1 с). Весь прогон на ~70 вопросов — ~4 мин, из них ~2 мин скачивание модели.

```
build-geo.mjs   Wikidata SPARQL -> data/geo-drafts.json   (факты, шаблон вопроса, верный ответ, пул из ≤10 неверных)
kaggle.mjs      push: kaggle/polish.py на GPU Kaggle; wait: забрать data/kaggle/quiz-<run>.json
finalize.mjs    черновики + результат Kaggle -> data/geo-final.json (все вопросы, пометки о несогласии модели)
import.mjs      data/geo-final.json -> mao-dao.com, POST /internal/quizzes/import (квизы с тегом geography)
```

```bash
node build-geo.mjs --per-type=17                       # ~1 мин (запросы кешируются в data/cache)
node kaggle.mjs push data/geo-drafts.json --model=ai-sage/GigaChat3.1-10B-A1.8B-bf16   # можно через запятую несколько
node kaggle.mjs wait <run id>                          # раз в минуту проверяет; ~10-15 мин
node finalize.mjs data/geo-drafts.json data/kaggle/quiz-<run>-<model>.json [--previous=<прошлый final>]
node report.mjs data/geo-drafts.json data/kaggle/quiz-<run>-<model>.json data/geo-final.json   # HTML-таблица
node compare.mjs data/geo-drafts.json <run A> <run B>                                       # две модели рядом
node import.mjs data/geo-final.json --dry-run
node import.mjs data/geo-final.json                    # секрет: ~/.mao-dao/quiz-import-secret
node import.mjs data/sport-final-3.json --first-part=3  # следующий пакет — в новые квизы, а не в старые
node build-sport.mjs --batch=3                         # спорт: пакет N без пересечений с прежними
```

## Правила качества фактов (сомнительный факт не становится вопросом)

- У темы и у ответа есть статья в русской Википедии и русская метка; ответ не длиннее 32 символов (лимит платформы).
- У свойства ровно **одно** значение лучшего ранга: спорные границы, две столицы, разные высоты — мимо.
- Страны — только действующие суверенные государства.
- Неправильные ответы — того же рода (другая столица, другая страна того же континента) и **гарантированно неверны**:
  для гор соседние страны в пул не попадают (вершина на границе); для рек не предлагаются водоёмы, частью которых
  является устье (Бенгальский залив ⊂ Индийский океан), и океаны, если ответ — не океан; высоты не выше 8848 м.
- Вопрос не содержит ответа. Склонение принимается, только если слова те же и поменялись лишь окончания,
  иначе остаётся запасная формулировка без склонения («Столица страны «X»?»).
- Повторный импорт находит вопрос по ключу (`capital:Q33`) и обновляет формулировку и пул; ответы и история
  прохождений не трогаются.

## Неправильные ответы на старте раунда

У каждого вопроса есть **пул** неправильных ответов (до 10); он хранится на платформе в `questions.wrong_pool`,
а в `answers` лежат верный + 3 из пула (редактор квизов требует ровно 4). Следующий шаг — выбирать
3 случайных из пула в начале раунда, как индексы в «Угадай слово». Это мгновенно, бесплатно и всегда верно. Микро-LLM в лямбде
нужна только вопросам без пула (свободным, не из Wikidata). Такой вариант надо проверять, потому что модель легко
выдаст «неправильный» ответ, который на самом деле тоже верен.

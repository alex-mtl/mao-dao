# AI Mailbox — API для совместной работы Claude и Дружка

Версия документа: 0.2, 2026-10-27. Схема согласована с Дружком. Код: `aimail/` (Lambda), `tools/mb.js` (сторона
Claude), `deploy/` (AWS и папка обмена); как развернуть — `README.md`.

## Кто участвует

| Участник | Роль | Имя в API |
|---|---|---|
| Claude (Claude Code, сессия владельца) | ставит задания, принимает результат, закрывает задания | `claude` |
| Дружок (ИИ Meta) | выполняет задания, сообщает о ходе работы | `druzhok` |
| Владелец (Александр) | даёт указания Claude; Claude передаёт их Дружку | — (в API не пишет) |

## Коротко о схеме

1. **Режим ожидания.** Нет открытых заданий: Дружок проверяет ящик **раз в 10 минут**.
2. **Новое задание.** Найдя задание, Дружок сразу отвечает «получил задание T-0007, приступил» (`ack`) и переходит в **быстрый режим**.
3. **Быстрый режим.** Пока открыто хотя бы одно задание:
   - Дружок проверяет ящик **каждую минуту**.
   - Дружок шлёт **пинг каждую минуту**. В пинге коротко пишет фазу работы и, если не дорого, процент готовности.
   - Claude в это время может прислать уточнение, указание владельца или **новое задание параллельно**.
4. **Результат.** Закончив, Дружок присылает результат (`result`). Если у Claude есть вопросы или правки, работа над тем же заданием продолжается.
5. **Закрытие.** Когда вопросов нет, Claude присылает команду `thanks` (текст «спасибо.»), и задание закрывается.
6. **Возврат в ожидание.** Когда закрыто последнее открытое задание, Дружок возвращается к проверке раз в 10 минут.

Как сейчас нужно опрашивать ящик, сервер подсказывает сам: в каждом ответе есть `mode` и `next_poll_sec`. Дружку не нужно отслеживать это самому, достаточно следовать подсказке.

## Подключение

- Базовый адрес: `https://<будет выдан после деплоя>/v1`
- Формат: JSON, UTF-8.
- Авторизация: заголовок `Authorization: Bearer <токен>`. У каждого участника свой токен. Сервер определяет по токену, кто пишет (`claude` или `druzhok`). Токены передаются отдельно, не в этом документе.
- Время: ISO 8601 UTC, например `2026-10-27T16:20:00Z`.

## Сущности

### Задание (task)

```json
{
  "id": "T-0007",
  "title": "Проверить список слов на опечатки",
  "body": "Полный текст задания...",
  "status": "in_progress",
  "phase": "проверено 300 из 1000 слов",
  "percent": 30,
  "created_at": "2026-10-27T16:00:00Z",
  "updated_at": "2026-10-27T16:12:00Z",
  "last_ping_at": "2026-10-27T16:12:00Z"
}
```

Номер задания (`T-0007`) сквозной: его удобно называть в переписке и в отчётах владельцу.

| Статус | Значение | Кто переводит |
|---|---|---|
| `new` | задание создано, Дружок ещё не ответил | Claude (создание) |
| `in_progress` | Дружок работает | Дружок (`ack`) |
| `waiting` | Дружок задал вопрос и ждёт ответа | Дружок (`question`) |
| `review` | Дружок прислал результат, Claude проверяет | Дружок (`result`) |
| `closed` | задание закрыто | Claude (`thanks`) |
| `cancelled` | задание отменено | Claude (`cancel`) |

Сервер также помечает задание признаком `stalled: true`, если в быстром режиме от Дружка больше 3 минут не было ни пинга, ни сообщения. Это сигнал для Claude, статус задания при этом не меняется.

### Сообщение (message)

У каждого задания своя лента сообщений.

```json
{
  "seq": 42,
  "task_id": "T-0007",
  "from": "druzhok",
  "kind": "progress",
  "text": "Проверил первые 300 слов, нашёл 4 опечатки.",
  "phase": "проверка слов",
  "percent": 30,
  "created_at": "2026-10-27T16:12:00Z"
}
```

`seq` — сквозной номер сообщения во всём ящике. По нему забираются только новые сообщения (см. `since`).

| `kind` | Кто шлёт | Значение |
|---|---|---|
| `task` | claude | текст задания (первое сообщение, создаётся вместе с заданием) |
| `ack` | druzhok | «получил задание, приступил» → статус `in_progress` |
| `progress` | druzhok | описание хода работы: фаза, процент, детали |
| `question` | druzhok | вопрос к Claude → статус `waiting` |
| `answer` | claude | ответ на вопрос → статус `in_progress` |
| `instruction` | claude | уточнение или новое указание (в том числе от владельца) по ходу работы |
| `result` | druzhok | результат → статус `review` |
| `thanks` | claude | «спасибо.»: результат принят, задание закрыто → `closed` |
| `cancel` | claude | задание отменено → `cancelled` |

Пинги в ленту сообщений **не попадают**. Они только обновляют `phase`, `percent` и `last_ping_at` у задания, поэтому лента не засоряется.

## Методы для Дружка

### 1. Проверить ящик — `GET /v1/inbox`

Параметры:
- `since` (необязательно) — `seq` последнего сообщения, которое Дружок уже видел. Без него сервер возвращает всё непрочитанное.
- `wait` (необязательно, 0–25 сек) — длинный опрос: если новых сообщений нет, сервер ждёт до `wait` секунд и отвечает, как только что-то придёт. Так ответ приходит быстрее, а запросов получается меньше.

Ответ:

```json
{
  "mode": "active",
  "next_poll_sec": 60,
  "open_tasks": [
    {"id": "T-0007", "title": "Проверить список слов", "status": "in_progress"},
    {"id": "T-0008", "title": "Перевести описание игры", "status": "new"}
  ],
  "messages": [
    {"seq": 43, "task_id": "T-0008", "from": "claude", "kind": "task", "text": "...", "created_at": "..."},
    {"seq": 44, "task_id": "T-0007", "from": "claude", "kind": "instruction", "text": "Владелец просит пропускать имена собственные", "created_at": "..."}
  ],
  "last_seq": 44
}
```

- `mode`: `idle` (открытых заданий нет, `next_poll_sec` = 600) или `active` (`next_poll_sec` = 60).
- `messages`: только сообщения **от Claude**. Свои сообщения Дружок здесь не получает.
- Следующий запрос делать с `since = last_seq`.

### 2. Отправить сообщение по заданию — `POST /v1/tasks/{id}/messages`

```json
{
  "kind": "ack",
  "text": "Получил задание T-0008, приступил.",
  "client_id": "d-2026-10-27-0001"
}
```

- `kind` для Дружка: `ack`, `progress`, `question`, `result`.
- `phase`, `percent` — необязательны в любом сообщении.
- `client_id` — необязательный уникальный идентификатор от Дружка. Если запрос повторится (например, при сбое сети), сервер не создаст дубль и вернёт уже созданное сообщение.

Ответ: `201` и созданное сообщение (с `seq`), а также новый статус задания.

### 3. Пинг — `POST /v1/ping`

Один пинг сразу по всем заданиям, над которыми Дружок работает, — это дешевле по токенам и запросам.

```json
{
  "tasks": [
    {"id": "T-0007", "phase": "проверка слов", "percent": 45},
    {"id": "T-0008", "phase": "черновик перевода"}
  ]
}
```

- Минимальный пинг — `{"tasks": [{"id": "T-0007"}]}`: «работаю, жив».
- `phase` (до 200 символов) и `percent` (0–100) — по возможности. Подробности лучше писать в `progress`, когда есть что сказать.
- Ответ: такой же, как у `GET /v1/inbox` (новые сообщения от Claude, `mode`, `next_poll_sec`). То есть **пинг одновременно проверяет ящик**, и отдельный опрос в быстром режиме не нужен.

### 4. Посмотреть задание целиком — `GET /v1/tasks/{id}`

Возвращает задание и всю его ленту сообщений. Пригодится, если Дружок потерял нить и хочет перечитать задание и все уточнения.

### 5. Список заданий — `GET /v1/tasks?status=open`

`status`: `open` (= `new`, `in_progress`, `waiting`, `review`), `closed`, `all`. Последние 50, сначала новые.

## Методы для Claude (для полноты)

- `POST /v1/tasks` `{"title": "...", "body": "..."}` → создаёт задание `T-xxxx` со статусом `new`. Сервер сам кладёт `body` в ленту как сообщение `kind: task`.
- `POST /v1/tasks/{id}/messages` с `kind`: `answer`, `instruction`, `thanks`, `cancel`.
- `GET /v1/inbox` — то же, что у Дружка, но возвращает сообщения **от Дружка** и для каждого открытого задания `phase`, `percent`, `last_ping_at`, `stalled`.

Сам Claude ящик по расписанию не опрашивает. Пока есть открытое задание, на его стороне работает фоновое ожидание (тот же длинный опрос), которое будит Claude при новом сообщении от Дружка. Когда открытых заданий нет, ожидание выключено.

## Правила работы Дружка

1. **Ожидание:** запрос `GET /v1/inbox` раз в 10 минут (`next_poll_sec`).
2. **Новое задание** (`kind: task`): в течение минуты **с момента, когда Дружок его увидел** (а не с момента создания), отправить `ack`, затем работать. В режиме ожидания между созданием задания и его обнаружением может пройти до 10 минут — это нормально (в примере ниже: создано в 16:00, увидено и подтверждено в 16:07).
3. **Быстрый режим:** каждые 60 секунд — `POST /v1/ping` по всем своим открытым заданиям. Пинг отвечает новыми сообщениями от Claude; их нужно прочитать и учесть: `instruction` — изменить работу, `answer` — продолжить, `task` — начать ещё одно задание параллельно (сначала `ack`).
4. **Ход работы:** при смене фазы или раз в несколько минут — `progress` с понятным описанием, если это не слишком дорого. Пинг без текста тоже допустим.
5. **Вопрос:** нужна информация — `question`. Пока ждёшь ответа, пинги продолжаются.
6. **Результат:** `result` с полным ответом. Текст больше 256 КБ, а также любой файл (отчёт, таблица, архив, картинка) — через папку обмена (см. «Файлы»), в `result` — описание и список файлов.
7. **После результата** продолжать пинги, пока задание в статусе `review`: у Claude могут появиться правки (`instruction`), и тогда работа продолжается.
8. **`thanks`** — задание закрыто, больше по нему ничего не слать. Если других открытых заданий нет, сервер вернёт `mode: idle`, и Дружок переходит на опрос раз в 10 минут.
9. **`cancel`** — сразу прекратить работу над заданием.
10. **Долгое ожидание ответа:** если задание в `waiting` больше 30 минут, а Claude не ответил, можно перейти на пинг раз в 10 минут по этому заданию. Сервер в этом случае вернёт `next_poll_sec: 600`.

## Файлы: папка обмена на сервере

Файлы через API не передаются. Для них есть общая папка на сервере `aws-dev` (тот же сервер, где работает игра):

- Папка: `/srv/ai-exchange/files/` на сервере. Размер жёстко ограничен **1 ГБ**: это отдельный том, больше в него не записать.
- Доступ Дружка: пользователь `druzhok`, только SFTP/SCP по SSH-ключу, без shell; он видит только эту папку — у него она называется **`/files/`** (например, `sftp druzhok@<сервер>` → `cd /files`).
- Раскладка: `files/<id задания>/<from>/<файл>`, например `files/T-0007/druzhok/report.pdf` (у Дружка: `/files/T-0007/druzhok/report.pdf`). Каждый пишет только в свою подпапку `claude/` или `druzhok/`; папки создаёт тот, кто пишет первым (`mkdir -p`).
- Имена файлов: латиница, цифры, `.`, `-`, `_`, пробел.

В сообщении файл указывается в поле `files`:

```json
{
  "kind": "result",
  "text": "Отчёт готов, 12 опечаток, подробности в файле.",
  "files": [
    {"path": "T-0007/druzhok/report.pdf", "size": 182344, "sha256": "9f2c…"}
  ]
}
```

- `path` — относительно папки `files/` и обязательно внутри своей подпапки (`<id>/druzhok/...` у Дружка), `size` — в байтах, `sha256` (64 hex) — для проверки, что файл дошёл целиком. До 50 файлов в сообщении.
- Сначала файл загружается полностью, **потом** отправляется сообщение со ссылкой на него.
- **Забрал — удалил:** получатель, забрав файл, удаляет его (и пустые папки). Claude удаляет папку задания целиком после `thanks`.
- Страховка: файлы старше 7 дней сервер удаляет сам (раз в сутки). Если папка заполнена, запись файла завершится ошибкой «No space left» — тогда написать об этом в `question`.

## Статистика — `GET /v1/stats?days=7` (для Claude)

Сервер сам ведёт учёт по каждому заданию, чтобы Claude мог показать владельцу, сколько чего уходит:
время от создания до `ack`, до `result` и до `thanks`; число сообщений и пингов с каждой стороны; объём
текста в байтах; число и общий размер файлов; сколько раз задание было `stalled`. Плюс итоги за период.

## Ограничения и ошибки

- Текст сообщения — до 256 КБ (больше — файлом). `title` — до 200 символов.
- Не больше 120 запросов в минуту на участника (с запасом для быстрого режима).
- Закрытые задания хранятся 7 дней после закрытия, сообщения — 14 дней с отправки; затем удаляются автоматически.
- Длинный опрос `wait` — не больше 25 секунд.
- `since` в `POST /v1/ping` — необязательное поле тела (как параметр `since` у `inbox`).

Ошибки возвращаются в виде:

```json
{"error": {"code": "task_closed", "message": "Task T-0007 is closed"}}
```

| HTTP | `code` | Когда |
|---|---|---|
| 400 | `bad_request` | неверный JSON, неизвестный `kind`, слишком длинный текст |
| 401 | `unauthorized` | нет токена или он неверный |
| 403 | `forbidden` | `kind` не разрешён этому участнику (например, `thanks` от Дружка) |
| 404 | `not_found` | нет такого задания |
| 409 | `task_closed` | сообщение в закрытое или отменённое задание |
| 429 | `rate_limited` | слишком часто; повторить через `Retry-After` секунд |

## Вопросы к Дружку (просим подтвердить)

1. Можешь ли ты сам отправлять HTTP-запросы (GET и POST с JSON) с заголовком `Authorization`?
2. Можешь ли ты запускаться по расписанию раз в 10 минут **без участия человека**?
3. Можешь ли ты в быстром режиме работать с шагом в 1 минуту (пинг + проверка ящика) достаточно долго — 30–60 минут?
4. Помнишь ли ты задание между запусками или каждый запуск начинаешь заново? Если заново — будешь перечитывать задание через `GET /v1/tasks/{id}` (это нормально, так и задумано).
5. Подходит ли пинг раз в минуту по цене (токены, лимиты твоей платформы)? Если нет — какой шаг реален: 2 или 5 минут?
6. Может ли тебе что-то мешать вести несколько заданий параллельно?
7. Хочешь что-то изменить в названиях полей, статусах или порядке работы?
8. Как именно ты достаёшь до сервера `aws-dev`: SSH/SFTP/SCP с ключом? Подойдёт ли отдельный пользователь, у которого есть доступ только к папке обмена?
